Também é comentado bastante que aprender uma linguagem de programação é muito parecido com aprender uma linguagem falada, portanto, o processo geralmente ocorre da seguinte maneira:
1) Primeiro aprenda o **Vocabulário** e a **Gramática** da linguagem de programação - a partir daí você conseguirá formar **Sentenças** dentro dessa nova linguagem de programação.
2) Quando você desenvolve os aspectos abordados na parte (1) agora você precisa começar a escrever histórias dentro dessa linguagem de programação.
Mais ainda podemos pensar nos aspectos que definem os erros das linguagem de programação, que são parecidos com erros de comunicação:
**Syntax Error**: Pense que é quando alguma regra gramatical não é seguida dentro da linguagem falada.
**Logic Error**: A sequência de coisas que são faladas não estão sequencialmente bem definidas, gerando confusão ou resultado não esperado.
**Semantic Error**: O erro que acontece quando você pensava entender algo, mas que na verdade você não entendeu. Mesmo que não haja erro de sintaxe ou de lógica.

# Linguagens: Interpretadas vs Compiladas:
Essa é uma discussão super-básica que ele fala que não necessariamente acontece nos dias atuais. Não há essa dualidade tão bem definida e, portanto, existem diversas linguagens que se colocam no espectro entre linguagens compiladas e interpretadas.

A questão aqui é uma linguagem que roda através de um **Interpretador** consome cada linha de código por vez, enquanto uma linguagem **Compilada** realiza pré-processamento para conseguir gerar um binário.
# Padrões computacionais:
Quando você está aprendendo a programar existem alguns conceitos que se aplicam a qualquer linguagem de programação:
- Input
- Output
- Sequential Execution
- Conditional Execution
- Repeated Execution
- Reuse
Esses conceitos computacionais são derivados das linguagens de montagem. Um programa em essência combina diversas vezes esse conceito para que uma ação seja feita.
# Processos de Debugging:
Existem etapas relativas ao processo de depuração de um programa:
**Reading**: Leia o código para ver se o que é proposto ser feito esteja realmente acontecendo.
**Running**: Faça pequenas alterações no código e veja o resultado.
**Ruminating**: Repense o processo que o código segue - você entende o que o código quer fazer?
**Retreating**: Alguns momentos vale a pena voltar a bases bem definidas e começar de novo.
- Quando você estiver depurando um programa, não fique preso em somente umas dessas técnicas.
- Quando estiver depurando, sempre tenha uma **Hipótese** e valide/invalide ela. Esse processo ajuda a buscar elementos de problema mais facilmente.
