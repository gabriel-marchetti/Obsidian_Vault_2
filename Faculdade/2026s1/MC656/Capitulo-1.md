# Conceito de Engenharia de Software
Práticas **Sistemáticas** para criação de sistemas complexos com qualidade. Portanto, a base da disciplina é a investigação e soluções de desafios enfrentados por sistemas.

**Conferência de OTAN** - Propostas para desenvolver software de modo que ele fique prático e tenha respaldo teórico.

**Frederick Brooks** - *Dificuldades Essenciais* e *Dificuldades Acidentais*. A primeira se refere à dificuldade inerente de uma área específica.
- Complexidade.
- Conformidade.
- Facilidade de Mudanças.
- Invisibilidade.

# Engenharia de Requisitos:
Como um sistema deve **operar** e o que deve **fazer**. 
Requisitos **Funcionais** e **Não-Funcionais**.

# Projeto de Software:
Definir as **Interfaces** - Interfaces Providas e Interfaces Requeridas.
Se a questão envolver um nível mais alto, podemos chamar de **Arquitetura de Software**.

# Construção de Software:
Definir os algoritmos e estruturas de dados que serão utilizados.
Definir frameworks e bibliotecas.
Definir Técnicas de tratamento de exceções.
Definir padrão de nomes e padrão de layout. 

# Testes de Software:
- Testes de Unidade.
- Testes de Integração.
- Testes de Performance.
- Testes de Usabilidade.

**Verificação**: Um sistema atende à sua especificação?
**Validação**: Um sistema atende às necessidades dos clientes?

# Manutenção e Evolução de Software:
- Corretiva
- Preventiva
- Adaptativa
- Refactoring
- Evolutiva

# Gerência de Configuração:
Controle de Versão com um Software como **GIT**.
Definição de políticas para gerenciar versões de um sistema - **Versionamento Semântico**.

# Gerência de Projetos:
**Lei de Brooks** - Incluir novos desenvolvedores em um software atrasado o fará ser mais atrasado.
Aumentar quantidade de desenvolvedores aumenta drasticamente o número de canais de comunicação.

# Processos de Desenvolvimento de Software:
Quais atividades e etapas devem ser seguidas para desenvolver um software.

**Processos Waterfall**: desenvolvimento *plan-driven*. 
Principal problema - Pressupõe que cada etapa é feita perfeitamente para a etapa seguinte.
**Processos Ágeis**: desenvolvimento liderado por pequenas iterações de mudanças e validados pelos usuários. 
Diversos métodos foram criados: *XP, Scrum, Kanban* e *Lean Development*.
Além disso popularizaram: *Testes Automatizados*,*test-driven development* e *integração contínua*.

# Modelos de Software:
**Forward Engineering** - primeiro criar o modelo para entendimento de alto nível.
**Reverse Engineering** - documentação de um código analisado através de modelos.

**UML** - notação gráfica para modelagem.

# Qualidade de Software:
**Qualidade externa** e **Qualidade interna**. 

# Classificação de Sistemas de Software:
**Bertrand Meyer** propõe a separação de categorias de software para definir princípios de engenharia para cada uma das categorias.
**Sistemas A** - Acute
**Sistemas B** - Business
**Sistemas C** - Casuais
