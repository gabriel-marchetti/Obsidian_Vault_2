## Roles and Responsibilities.
-> Contributors, Core Contributors e Technical Committee.
	Contributors do not have voting rights.

### Core Contributors.
-> All of them have voting rights.
-> New members can be nominated by old members (specific roles).
-> Teams:
	Contributor Experience Team:
		- Help with triage of issues and pull requests.
		- Notice any repeating patterns that people might struggle.
		- Improve communication and control issue tracker.
	Communication Team:
		- Develop public awareness of scikit-learn. (features, usage and branding).
		- Social networks and produce materials
	Documentation Team:
		- Develop/Analyze documentation.
		- Their thoughts on documentation are correct and decisive.
		- They have permission for merge pull requests.
	Maintainers Team:
		- Community Members that are engaged with the project.
		- Review code Contributions.
		- Merge APPROVED pull requests.
		- Vote for or against a merging pull-request.
		- Decide major changes in the API.

### Technical Committee.
-> Strategic Planning.
-> Approve Changes in Governance Model.
-> Analyze the consequence of a decision and make it clear for the rest of the team.
-> Act when consensus is not achieved.

## Decision Making Process.
-> Decisions are made through discussion at the Mailing List and the Issue Tracker. (Sometimes they make it private)
-> "Consensus-Seeking" process.
-> Call for a vote -> SLEPs (Scikit-Learn Enhancement Proposal) which is a document that follow a pattern.
-> If majority is not achieved through Core Contributors, then it is passed to the Technical Committee (TC) and follows similar steps.

- Minor Code and Documentation changes - require a +1 by a Core Contributor and NO -1 by a Core Contributor.
- Code Changes and Major documentation changes - require a +2 and NO -1.
- Changes to the API, Changes to Dependencies - Follow process described above.
- Changes to the governance model - Follow process described in SLEP020.

OBS: -1 vetos can be appealed to the community process.

# Contributing.
-> Scikit-Learn is selective when adding new algorithms.
-> Recommended to work on known issues.

-> Automated Contributions Policy: They do not accept issues generated by IA. Humam-to-Humam discussion.

## Submitting a bug report or a feature request:
-> Issue tracker manages this part.
-> Verify that there are not issues/PRs that already deals with this error.
-> If an Algorithm or a Feature Request - [New Algorithm Requirements](https://scikit-learn.org/stable/faq.html#what-are-the-inclusion-criteria-for-new-algorithms) (TO-DO: NÃO LI AINDA)

## How to make a good bug report:
-> Short reproducible code snippet.
-> If no snippet be specific: what estimators, functions are involved.
-> If an exception if raised: Provide the full traceback.
-> Provide OS and Version Number. Provide version of Python, Scikit-Learn, Numpy and Scipy versions.
To show all this information:
```Python
python -c "import sklearn; sklearn.show_versions()"
```
-> Follow some code formatting as shown in: [Code Formatting](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-and-highlighting-code-blocks) (NÃO OLHEI DIREITO)
