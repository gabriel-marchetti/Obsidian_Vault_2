# Inteligências Artificiais e Machine Learning:
- Atualmente estamos em uma bolha de IA - Pode estourar em qualquer momento. A maior parte das empresas americanas em tecnologia está tentando criar servidores para aguentar a alta demanda por IAs, contudo a IA generativa é a maneira menos eficiente de gerar texto. Metades do servidores, hoje em dia, estão sendo usados para rodar GPUs para treinar e rodar alguns modelos.
- Aprender a utilizar LLMs de modo eficiente, isto é, criar software que gere bem as respostas. 
- Arquitetura de LLMs são altamente brute-force.
- Front-End já lida com respostas previsíveis sem rodar dentro do modelo.
- Toda a tecnologia deriva da fundação - Desse modo, modificar esses modelos exige um conhecimento profundo dos modelos e tudo mais.
- Não importa se sair o GPT-5, GPT-6, ... as LLMs não irão substituir programadores - A arquitetura possui erros intrínsecos que não permitem que elas evoluam sem aumentar exponencialmente o poder computacional (janela de contexto maior, modelo maior, ...).
- Uma AGI deveria gerar o código do GPT-5, GPT-6, ...
- Probabilidade/Estatística são as principais matérias para entender IA.
- Teoria da Informação - Tokens (Fragmentos de palavras) - N grams - Banco de Dados com relevância.
- Quanto maior o prompt, pior a probabilidade do contexto (Algoritmos de Atenção, Diminishing Returns).
- Hoje em dia é muito fácil fazer código, até a IA consegue fazer - O difícil é conseguir fazer um código bom: performático, seguro e tudo mais.
- Única forma de gerar sistemas grandes é através de programadores - A AI pode ser utilizada como uma nova Stack-Overflow.
- Arquitetura de Von Neumann e Arquitetura de Turing existem limitações conhecidas há diversos anos - Computador é uma aproximação do mundo real.
- A matemática não possui respostas para tudo - Desse modo, como os computadores estão no arcabouço da matemática, então existem respostas não respondidas por computadores.
- Cérebro Humano não tem nada a ver com Arquiteturas Cognitivas de IA - Essas técnicas tentam assimilar essas características - Um neurônio armazena diversas informações e por si só é um sistema.
# Arquiteturas de computadores.
- Arquiteturas de Computadores - **Translation Layers** - Traduzir de x86 para PowerPC, por exemplo.
- Século XXI - Poder computacional proporcionou possibilidade de **Translation Layer**.
- Tecnologia não é investimento, é custo - Traduzir x86 para ARM deve vir com vantagens econômicas.
- O topo da cadeia (Big Techs) já utilizam ARM e outras arquiteturas, contudo a cauda longa ainda tem muita inércia de mudança.
- 1990s - Aumentar frequência de processamento.
- 2000s - Multicore.
- x86 já faz tradução de CISC para RISC. Antes havia muito custo para processar os comandos.
- Porque existe essa diferença entre CISC e RISC - Até 1980 não havia muito o uso de compiladores, portanto, para escrever código performático era necessário escrever em Assembly.
- Com o avanço dos computadores - Melhora dos compiladores - 1990s código fonte para binário.
- Desvantagem para o mundo Intel - Antes precisavam de uma instrução que faziam várias coisas, isso se adequava à época. Contudo, hoje em dia essa dificuldade da simplicidade das instruções não é um problema. 
- Bons compiladores implicaram no uso de arquiteturas RISC.
- [[Chris-Lattner]] criador do LLVM - Possibilitou a transição para ARM dentro da Apple.
- Subsistemas dentro de uma CPU - Expansões da Arquitetura - Software que emula isso.
# Carreiras e Dicas.
- Se todo mundo consegue fazer com mínimo esforço, então vale pouco.
- Gerar código não é programar.
- Não preciso de uma IA para estragar a carreira de um programador - Utilizar código para resolver problemas.
- O que eu estou fazendo tem valor ou não tem valor? - Sistemas escalam, tem protótipo e por ai vai.
- Protótipo para avaliar um conceito - Deu certo -> Quais os gargalos esse sistema tem?
- Trocar de ferramentas e framework deve ser algo comum - Não se fidelize a uma ferramenta específica.
- Ferramentas erradas nos lugares errados geram problemas.
- Aprender a tomar decisões rápidas - Se a decisão é leve, então tome essa decisão e veja as consequências. (Se olhe no espelho depois para avaliar um erro).
- Todo influencer fala besteira - Eles tem a motivação de monetizar o conteúdo.
- Tudo que eu fizer pela primeira vez ficará uma porcaria.
- Toda informação útil provavelmente está dentro da documentação.
- Se proteger de cometer erros é um jeito de não aprender.
- Perguntar o porquê existe de cada coisa? Quais problemas eles tentaram resolver? Você conseguiria resolver esse problema? Como você resolveria esse problema?
- Você tem medo de fazer perguntas, porque você tem medo de errar e acha que errar é um problema.
